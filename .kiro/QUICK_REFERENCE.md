# SunStudio 快速参考卡片

> 📋 给开发者（包括 AI）的速查手册

---

## 🚀 5 秒速查

**核心原则：**
- 逻辑分层，各司其职
- App.tsx 是高优先级保护区
- 给新增功能一个唯一合法入口

**修改 App.tsx 前必须：**
1. 说清楚为什么要动
2. 说清楚要怎么动
3. 说清楚有什么后果
4. 等待用户确认

---

## 📁 目录结构

```
src/
├── App.tsx              # 主入口（只做组合和配置）
├── components/          # UI 组件（只做展示）
├── hooks/               # 交互逻辑（处理用户操作）
├── core/                # 底层（不依赖 React）
│   ├── stores/          # 数据管理（Zustand）
│   ├── utils/           # 纯计算
│   └── registry/        # 注册表
├── services/            # 外部服务
└── types.ts             # 类型定义
```

---

## 🎯 添加新功能的唯一入口

| 需求 | 唯一入口 | 禁止 |
|------|---------|------|
| 添加新节点类型 | `core/registry/NodeRegistry.ts` | ❌ 改 App.tsx |
| 添加新交互逻辑 | `hooks/` 对应的 Hook | ❌ 在 Node.tsx 塞逻辑 |
| 添加新数据管理 | `core/stores/` 对应的 Store | ❌ 在 App.tsx 加 useState |
| 添加新计算逻辑 | `core/utils/geometry.ts` | ❌ 在 UI 文件里写计算 |

---

## 🔄 数据流（单向）

```
用户操作
  ↓
UI 组件（触发事件）
  ↓
Hook（处理交互逻辑）
  ↓
Store（更新状态）
  ↓
UI 组件（重新渲染）
```

---

## ✅ 允许修改 App.tsx 的情况

1. **架构调整** - 添加全局 Provider、调整路由
2. **重构过程中** - 抽离逻辑、修复致命 Bug
3. **用户明确要求** - 用户批准了修改方案
4. **紧急修复** - 崩溃、数据丢失、安全漏洞

**修改前必须：**
- 说清楚为什么、怎么动、有什么后果
- 等待用户确认

---

## 🚫 绝对禁止

- ❌ 在 App.tsx 写业务逻辑
- ❌ 在 UI 组件里写几何计算
- ❌ 跨层混用（UI 直接操作 Store）
- ❌ Map/Array 混用
- ❌ 使用英文回复用户

## 📋 开发检查清单

### 添加新功能前

- [ ] 这个功能属于哪一层？（UI / Hooks / Core）
- [ ] 这个功能的唯一入口是什么？
- [ ] 需要修改 App.tsx 吗？如果需要，为什么？
- [ ] 有没有其他方案不修改 App.tsx？

### 修改 App.tsx 前

- [ ] 为什么必须改 App.tsx？
- [ ] 不改会有什么问题？
- [ ] 有没有其他方案？
- [ ] 具体要改哪些行？
- [ ] 会影响哪些功能？
- [ ] 用户同意了吗？

### 提交代码前

- [ ] 代码放在正确的层了吗？
- [ ] 有没有跨层混用？
- [ ] 有没有在 UI 组件里写业务逻辑？
- [ ] 编译通过了吗？
- [ ] 功能测试通过了吗？

## 🌐 语言规则

**必须使用中文进行所有交流和文档编写。**

- ✅ 回复用户：中文
- ✅ 编写代码注释：中文
- ✅ 编写文档：中文
- ❌ 禁止使用英文（除非代码本身需要）

---

## 🎯 核心目标

**不是控制代码行数，而是控制代码职责。**

**App.tsx 是高优先级保护区，轻易不能动。**

**如果要动，必须说清楚：为什么、怎么动、有什么后果。**

**以后加功能，通过扩展模块实现，而不是修改 App.tsx。**

**记住：这不是建议，这是规则。**
