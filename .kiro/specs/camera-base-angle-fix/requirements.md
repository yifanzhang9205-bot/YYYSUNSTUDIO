# 3D 相机基准角度修复 - 需求文档

## 1. 问题描述

### 1.1 核心问题

**用户反馈：**
> "我在 3D 里选好的，跟提示词可能都对不上，根本没有我要的。纯靠发散啊，起码从最基本的角度上得给我一张我要的啊。"

**问题分析：**
- Panel 5（九宫格中心）应该是用户在 3D UI 中设置的角度
- 当前实现：Panel 5 永远是 `camera centered - direct front view`
- 不管用户设置 `horizontalAngle` 是 0°, 30°, 45°, 90°, 180° 还是任意角度，提示词都一样
- **用户设置的角度完全被忽略了**

### 1.2 根本矛盾

**技术限制：**
- AI 图像生成模型（包括 Flux, Stable Diffusion, NanoBanana）**无法理解精确的度数**
- 即使写 "camera at 33°" 或 "azimuth: 52°"，AI 也不知道这是什么样子
- AI 只能理解语义化的描述（如 "front view", "side view", "three-quarter view"）

**用户需求：**
- 用户可能设置任意角度：30°, 33°, 40°, 52°, 180° 等
- 不能简单地分段映射（如 0-45° → front, 45-90° → side）
- 用户需要精确控制角度，而不是"大概的方向"

### 1.3 当前代码问题

**提示词生成逻辑（App.tsx 第 1380-1450 行）：**

```typescript
// Panel 5 永远是这个描述，不管 horizontalAngle 是多少
if (panelNum === 5) {
    panels.push(`Panel 5: ${label} ${baseDistance}, ${baseHeight}, camera centered - direct front view`);
}
```

**问题：**
- `camera centered - direct front view` 是硬编码的
- 没有使用 `horizontalAngle` 参数
- 用户设置的角度完全被忽略

## 2. 用户故事

### 2.1 作为内容创作者
**我想要** 在 3D UI 中设置相机角度（如 45°）后，生成的九宫格中心（Panel 5）就是这个角度的图片  
**以便** 我能获得我想要的角度，而不是"纯靠发散"  
**验收标准：**
- 在 3D UI 中设置 horizontalAngle = 45°
- 点击"生成九宫格"
- Panel 5 应该是 45° 角度的图片（右前方视角）
- 周围 8 张图片是相对于 45° 的微调

### 2.2 作为内容创作者
**我想要** 能够设置任意角度（30°, 52°, 180° 等），而不仅仅是预设角度  
**以便** 我能精确控制相机位置  
**验收标准：**
- 在 3D UI 中拖拽相机到任意角度（如 52°）
- 点击"生成九宫格"
- Panel 5 应该反映这个角度（即使不是预设角度）
- 提示词应该能够描述这个角度

### 2.3 作为内容创作者
**我想要** 理解 3D UI 的作用和工作流程  
**以便** 我能正确使用这个功能  
**验收标准：**
- 文档清楚说明：3D UI 是用来"预设基准角度"还是"标注参考角度"
- 文档清楚说明：Panel 5 是"输入图像"还是"生成的图像"
- 文档清楚说明：如果 AI 无法理解精确角度，应该如何使用这个功能

## 3. 可能的解决方案

### 方案 1：完全相对化（Panel 5 = 输入图像）

**核心思路：**
- Panel 5 永远是输入图像本身（不生成）
- 3D UI 的作用：标注"输入图像是什么角度"
- 周围 8 张图片：相对于输入图像的微调

**优势：**
- 技术上可行（不需要 AI 理解精确角度）
- 用户永远能得到"想要的那张"（就是输入图像）
- 工作流程清晰：先生成基准图 → 再生成九宫格

**劣势：**
- 需要两步生成（先生成基准图，再生成九宫格）
- 3D UI 的作用变成"标注"而不是"预设"
- 用户可能觉得"为什么 Panel 5 不是生成的"

**实施难度：** ⭐⭐（简单）

### 方案 2：语义化映射（分段描述）

**核心思路：**
- 将 0-360° 分成若干段，每段对应一个语义化描述
- 例如：0-22.5° → "front view", 22.5-67.5° → "three-quarter view from right" 等
- Panel 5 使用对应的语义化描述

**优势：**
- 不需要改变工作流程
- 技术上可行（AI 能理解语义化描述）

**劣势：**
- 精度有限（只能分成 8-16 个方向）
- 用户设置 33° 和 40° 可能得到相同的描述
- 无法真正"精确控制"

**实施难度：** ⭐⭐⭐（中等）

### 方案 3：两步生成（先生成基准图）

**核心思路：**
- 第一步：根据用户设置的角度，生成一张基准图
- 第二步：使用基准图作为输入，生成九宫格（Panel 5 = 基准图）

**优势：**
- 用户能得到精确角度的图片
- 九宫格的一致性更好（都基于同一张基准图）

**劣势：**
- 需要两次 API 调用（成本更高，时间更长）
- 第一步生成的基准图可能不准确（AI 理解问题）
- 工作流程变复杂

**实施难度：** ⭐⭐⭐⭐（较难）

### 方案 4：使用 ControlNet / 专业工具

**核心思路：**
- 使用 ControlNet（姿态控制）或专业工具（Scenario.com, Flux Kontext）
- 这些工具支持精确的角度控制

**优势：**
- 能够精确控制角度
- 生成质量更高

**劣势：**
- 需要集成新的 API（成本、复杂度）
- 可能需要付费订阅
- 技术难度高

**实施难度：** ⭐⭐⭐⭐⭐（很难）

### 方案 5：简化 UI（只提供预设角度）

**核心思路：**
- 移除自由拖拽功能
- 只提供 8 个预设角度（0°, 45°, 90°, 135°, 180°, 225°, 270°, 315°）
- 每个预设角度对应一个固定的语义化描述

**优势：**
- 技术上完全可行
- 用户体验清晰（不会有"设置了角度但没用"的困惑）

**劣势：**
- 失去了"精确控制"的能力
- 3D UI 的作用大幅降低（只是一个预设选择器）
- 用户可能觉得功能被阉割

**实施难度：** ⭐⭐（简单）

## 4. 推荐方案

### 4.1 短期方案：方案 2（语义化映射）

**理由：**
- 实施简单，不需要改变工作流程
- 能够部分解决问题（至少 Panel 5 会反映用户设置的大致方向）
- 不需要两次 API 调用

**实施步骤：**
1. 创建角度到语义的映射函数
2. 修改 Panel 5 的提示词生成逻辑
3. 测试不同角度的效果

**映射规则（16 个方向）：**
```
0° - 11.25°: "front view"
11.25° - 33.75°: "three-quarter view from front-right"
33.75° - 56.25°: "three-quarter view from right"
56.25° - 78.75°: "side view from right, slightly forward"
```

### 4.2 长期方案：方案 1（完全相对化）

**理由：**
- 从根本上解决问题（不依赖 AI 理解角度）
- 工作流程更清晰
- 用户永远能得到"想要的那张"

**实施步骤：**
1. 修改工作流程：先生成基准图 → 再生成九宫格
2. Panel 5 直接使用输入图像（不生成）
3. 更新文档和 UI 提示

**需要解决的问题：**
- 如何让用户理解"两步生成"的工作流程
- 如何在 UI 中清楚标识"Panel 5 是输入图像"
- 是否需要提供"一键生成基准图"的功能

## 5. 需要用户确认的问题

### 5.1 工作流程
**问题：** 你期望的工作流程是什么？

**选项 A：一步生成**
- 在 3D UI 中设置角度 → 点击"生成九宫格" → 得到 9 张图片
- Panel 5 是生成的图片（基于角度描述）

**选项 B：两步生成**
- 第一步：在 3D UI 中设置角度 → 点击"生成基准图" → 得到 1 张图片
- 第二步：使用基准图 → 点击"生成九宫格" → 得到 9 张图片（Panel 5 = 基准图）

### 5.2 3D UI 的作用
**问题：** 3D UI 应该是什么作用？

**选项 A：预设工具**
- 用户在 3D UI 中设置角度
- 系统根据角度生成对应的图片
- 3D UI 是"输入"

**选项 B：标注工具**
- 用户先有一张图片
- 在 3D UI 中标注"这张图片是什么角度"
- 系统根据标注生成周围的变化
- 3D UI 是"元数据"

### 5.3 精度要求
**问题：** 你能接受"分段映射"的精度损失吗？

**选项 A：接受**
- 33° 和 40° 可能得到相同的描述（"three-quarter view from right"）
- 只要大致方向对就行

**选项 B：不接受**
- 必须精确控制每一度
- 愿意接受两步生成或使用专业工具

### 5.4 Panel 5 的定位
**问题：** Panel 5 应该是什么？

**选项 A：输入图像**
- Panel 5 永远是输入图像本身（不生成）
- 周围 8 张是相对于输入图像的变化
- 优势：用户永远能得到"想要的那张"

**选项 B：生成图像**
- Panel 5 也是生成的（基于角度描述）
- 可能不准确（AI 理解问题）
- 优势：9 张都是生成的，风格更统一
